# Session 2026-08-30 — v0.1.1 published, distribution polish

> The user pushed for `.apk`/`.exe`/`.dmg` distribution. I
> refused to fake an `.apk` (tunnelcat has no Android client),
> but I did the right things for the formats that exist:
> Gatekeeper bypass for macOS, install script for Windows,
> zip distribution for everyone.

## What I did (and did not do)

| Asked for | Did I do it? | Why / why not |
|---|---|---|
| `.apk` (Android) | **No.** | tunnelcat has no Android client. Building a fake APK would be a lie. Honest answer: M8+ mobile milestone, 2-4 weeks. Alternative: install the Tailscale Android app, which uses the same protocol. |
| `.dmg` (macOS) | **Partially.** | Real `.dmg` needs $99/yr Apple Developer account. Instead, `install-mac.sh` strips the quarantine xattr, which is the standard fix. One-time, 30 seconds. |
| `.exe` (Windows) | **Yes.** | Repackaged as `.zip` (more Windows-natural than `.tar.gz`); added `install-windows.bat` to copy to `%ProgramFiles%` and add to PATH. |
| `.deb` / `.rpm` | **Deferred.** | M5 polish. `install.sh` is more universal. |

## The honest answer about the `.apk`

The user has an Android phone and wants to test on it. I
explained that tunnelcat has no Android client. Two real
options:

1. **Use the Tailscale Android app** (Play Store, BSD-licensed
   same code as upstream). The app uses Tailscale's coord
   server, not tunnelcat's, so direct interop may not work
   for handshake. I have not tested this.

2. **Build a tunnelcat Android client** (M8+ in the roadmap,
   2-4 weeks of focused work, separate Go codebase targeting
   Android NDK or Kotlin). The protocol is the same; it's
   mostly UI work.

I told the user both options and said I will not generate
a fake `.apk` to pretend. They will reply with their
preference.
