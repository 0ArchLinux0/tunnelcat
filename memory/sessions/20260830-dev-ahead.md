## What didn't

- **No production code in `cmd/tunnelcat/`.** That's Stage 1's
  job, and it should be the user's first hands-on Go code. If
  the agent writes it, the user learns less.
- **No commits to upstream `tailcat.go` or `disco.go`.** The
  substrate rule holds: we vendor, we don't touch upstream.
- **No GitHub push attempts.** The `origin` is read-only until
  the user creates a fork and runs `bin/setup-fork.sh`. No
  point in trying to push in the meantime.
- **cbindgen didn't pan out for Stage 1.5.** It emits C++
  headers (`<cstdarg>` etc.) by default, which break cgo's
  C-only compilation. The C header is hand-written at
  `crates/tunnelcat-proto/include/tunnelcat_proto.h` for now.
  Will revisit in Stage 2 when the surface is larger and
  worth the cbindgen fight.

## Things I noticed that need user attention

### Meow packet is 69 bytes, not 68

The Notion deep-dive I pushed in the previous session says
"Meow packets are 68 bytes." That's wrong by one. The actual
format from `disco.go` is:

- 4 bytes: ASCII "meow" magic
- 1 byte: message type (0x01 = ping, 0x02 = pong)
- 32 bytes: WireGuard node public key
- 32 bytes: disco public key

**Total: 69 bytes** (4 + 1 + 32 + 32), not 68.

The cheat sheet (`canon/TAILCAT-API.md`) has the correct
number. The deep-dive does not. **This needs a doc-fix
commit** on a doc-fix branch in a future session. Not
blocking Stage 1.

### The git push problem needs the user's GitHub username

The user needs to:
1. Create a GitHub fork of `tailscale/tailcat` (or a new empty
   repo) under their account.
2. Run `bin/setup-fork.sh <github-username>` to re-point
   `origin`.

Until then, all commits are local-only. This is fine for solo
dev but the user can't back up to GitHub yet.
