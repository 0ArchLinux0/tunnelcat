## Real bugs I caught and fixed (all caught by tests)

1. **`key.NodePrivate.AppendText` produces `privkey:<hex>`, not `nodekey:<hex>`.** The doc and my M1 plan were wrong. Private keys use the `privkey:` prefix; public keys use `nodekey:`. Fixed: the file stores the private key in the `nodekey:` form (stripped of `privkey:`) for human inspection, and Load strips both prefixes to be lenient.
2. **`filepath.Ext` returns the last extension only.** `foo.private.json` has ext `.json`, not `.private.json`. `List()` was finding zero files. Fixed: use `strings.HasSuffix`.
3. **`TestRunUnknownSubcommand` clashed with the new `identity` subcommand.** Fixed: removed `identity` from the unknown list.

## What's NOT done (deliberate)

The M1.4 sub-step in the plan also said "use the identity in up/dial." That means `tunnelcat up --identity=default` should load the saved key as the server's key, instead of generating ephemeral. **That wiring is a separate sub-step** (let's call it M1.4.5). I left it out of this commit because:

1. The user said "do M1.3-M1.5, then check in." M1.5 is the third in that range; the wiring is a fourth step.
2. The wiring should land when we have M1.6 (contacts) so identity + contacts integrate together.
3. Identity is a usable standalone feature right now (init / show / list / delete). Users who want the full integration get it in the next sub-step.
